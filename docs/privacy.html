Zero-Knowledge & Local-First Privacy Architecture

JalaDesk (com.jaladesk.app) is engineered with a strict Zero-Knowledge, Local-First architecture spanning four unified surfaces: Desktop Studio with 1-Click Local Web Bridge (macOS & Windows), Android Foldable Flex Mode & iOS/iPadOS apps, the Zero-Knowledge Web PWA (/app/), and the Self-Hosted Docker Web Gateway (JSR1). You can operate JalaDesk without registering an account or connecting any cloud storage service.

Developer and Data Controller Rizky Bachtiar Irwanto operates zero backend, telemetry, analytics, or session relay servers. When using the Web PWA (/app/) for live RDP, VNC, SSH, or SFTP sessions, traffic routes exclusively through your own Desktop 1-Click Web Bridge or your Self-Hosted Docker Gateway (JSR1) on user-owned infrastructure authenticated with 60-second single-use WebSocket tickets. We never collect, transmit, inspect, rent, or sell your personal information, server IP addresses, host inventories, SSH private keys, passwords, or RFC 6238 TOTP two-factor authentication secrets.

Data Stored Locally on Your Device

All connection configurations, bastion jump-host topologies, credentials, and two-factor authentication seeds reside locally on your device inside an authenticated encrypted container (.rwdoc, .rtsz, .jaladesk, or .jvault). Inside the Zero-Knowledge Web PWA (/app/), vault cryptography runs strictly in browser memory via WebCrypto AES-256-GCM and PBKDF2-HMAC-SHA256, ensuring zero plaintext credentials ever touch localStorage, IndexedDB, or remote servers.

Security Layer Standard / Mechanism Protection Boundary
Key Derivation scrypt & PBKDF2-HMAC-SHA256 Derived strictly on-device (native crypto or browser WebCrypto in /app/) from your Master Passphrase using 100,000 iterations and unique cryptographic salts.
Vault Cipher AES-256-GCM Authenticated client-side encryption with random initialization vectors and 128-bit integrity tags preventing tampering across Desktop, Mobile, and Web PWA.
Hardware Enclave Keychain · DPAPI · Biometrics Optional local unlock via macOS Keychain, Windows DPAPI, Android BiometricPrompt, or Apple Secure Enclave (Face ID / Touch ID). Biometric data never leaves OS hardware.
Self-Hosted Gateway JSR1 · 60s WS Tickets Desktop 1-Click Web Bridge and Self-Hosted Docker Gateway (JSR1) run strictly on user-owned infrastructure using ephemeral 60-second single-use WebSocket tickets with zero developer relay servers.
Clipboard Scrubber 30-Second Auto-Purge Passwords, private keys, and TOTP tokens copied in JalaDesk are automatically cleared from system clipboard memory after the configured TTL window.

Optional Google Sign-In & Google User Data Disclosures

JalaDesk provides an optional, user-initiated Google Drive Cloud Sync capability so you can synchronize your encrypted vault across Desktop Studio, Android Foldables & iOS, and the Zero-Knowledge Web PWA (/app/) using your Google Account. If you do not activate Google Drive Cloud Sync, JalaDesk makes zero requests to Google APIs.

Exact Google OAuth 2.0 Scopes Accessed

When you explicitly initiate Sign in with Google inside JalaDesk, native apps authenticate directly with Google using OAuth 2.0 with PKCE and the Web PWA (/app/) authenticates directly via client-side Google Identity Services (GIS), requesting only the following scopes:

OAuth 2.0 Scope Data Accessed How JalaDesk Uses & Stores Data
openid OpenID Connect account subject identifier Verifies the authenticated OAuth 2.0 session directly between your device and Google (accounts.google.com and oauth2.googleapis.com). Stored strictly locally on your device.
userinfo.email Primary Google account email address Displayed locally inside JalaDesk's Cloud Sync settings view so you can verify which Google account is bound. Never sent to any developer server.
userinfo.profile Basic Google profile display name and avatar metadata Displayed locally in JalaDesk's Cloud Sync identity bar on your device. Never transmitted to any developer server or third party.
https://www.googleapis.com/auth/drive.appdata Application-specific hidden appDataFolder in your Google Drive (jaladesk-vault-v1.jvault / jaladesk_vault_sync_v1.jdesk) Reads, creates, updates, and deletes only JalaDesk's own client-side encrypted vault container inside your hidden Google Drive Application Data folder. JalaDesk cannot view, list, read, modify, or delete any personal files, folders, documents, or photos in your Google Drive.

Client-Side Encryption & Storage of Google Drive AppData

Prior to uploading any vault payload to Google Drive appDataFolder, JalaDesk derives a 256-bit encryption key locally on your device from your Vault Master Passphrase via PBKDF2-HMAC-SHA256 (100,000 iterations) and encrypts the vault client-side using authenticated AES-256-GCM encryption.

  • Plaintext server hostnames, usernames, passwords, SSH private keys, and RFC 6238 two-factor secrets never leave your device unencrypted.
  • Your Vault Master Passphrase is never transmitted to Google or to Rizky Bachtiar Irwanto.
  • OAuth 2.0 access and refresh tokens remain exclusively on your local device and communicate directly over HTTPS (TLS 1.2+) with official Google API endpoints.

Strict Prohibition on Data Sharing, Sale, Advertising & AI Training

  • Zero Developer Server Transmission: No Google user data (openid, email address, profile metadata, OAuth tokens, or drive.appdata payloads) is ever sent to or stored on any server controlled by Rizky Bachtiar Irwanto.
  • Zero Third-Party Transfers or Sales: JalaDesk never sells, rents, licenses, trades, or shares Google user data with third parties, advertisers, analytics networks, or data brokers.
  • Zero Advertising or Profiling: Google user data is never used for serving advertisements, personalized retargeting, or creditworthiness evaluation.
  • Zero AI / ML Training: Google user data and synced vault containers are never used to train, fine-tune, or evaluate generalized artificial intelligence (AI) or machine learning (ML) models.

Network & Operating System Permissions

JalaDesk requests only the minimal operating system and browser permissions required to execute connections and security actions explicitly initiated by you:

  • Internet & Local Network Access (android.permission.INTERNET / Desktop sockets): Used exclusively to establish direct remote sessions (RDP, VNC, SSH, SFTP, and bastion Jump Hosts) to targets you configure, bind your Desktop 1-Click Local Web Bridge, perform local LAN mDNS vault pairing, or synchronize encrypted vault files directly with your selected storage provider (Google Drive appDataFolder, SFTP, WebDAV, or GitHub Gist).
  • Web PWA Browser APIs (/app/ WebCrypto & WebSockets): Used strictly client-side to seal/unseal AES-256-GCM vaults in memory, exchange optional Google Identity Services (drive.appdata) requests directly with Google, and stream encrypted JSR1 frames to your own Local Web Bridge or Self-Hosted Docker Gateway using 60-second single-use WebSocket tickets with zero developer relay servers.
  • Biometric Hardware Access (android.permission.USE_BIOMETRIC / Face ID / Touch ID): Used strictly locally via OS hardware security APIs to unlock your encrypted vault or App Lock PIN.

Data Retention, Deletion & Revoking Google OAuth Permissions

Because JalaDesk stores data locally on your device (or in encrypted client-side browser storage for the Web PWA) and, only when opted in, inside your own Google Drive appDataFolder, you retain full administrative control over retention and deletion at every stage:

  1. Disconnect Google Account in JalaDesk: Open the Cloud Sync studio inside JalaDesk (Desktop, Mobile, or Web PWA) and select Disconnect. JalaDesk immediately erases local OAuth 2.0 / GIS tokens and cached Google account email and profile metadata from your device or browser session.
  2. Delete Synced Vault Data from Google Drive: Delete the synced vault container directly from JalaDesk's Cloud Sync settings, or open Google Drive on the web and navigate to Settings, then Manage apps, then JalaDesk, then Options, then Delete hidden app data to permanently purge JalaDesk's appDataFolder storage.
  3. Revoke OAuth 2.0 Access via Google Account Security: Visit https://myaccount.google.com/permissions at any time, select JalaDesk, and click Remove Access to immediately invalidate all OAuth tokens granted to JalaDesk.
  4. Remove Local Device Vaults & Browser Data: Deleting your local vault files, clearing browser site data for /app/, stopping your Self-Hosted Docker Gateway container, or uninstalling JalaDesk immediately removes all locally stored connection inventories and encrypted credentials.
