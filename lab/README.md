# Lab acceptance RDP

`rdp-acceptance.json` memuat hasil per baseline. `npm run test:live` mengharuskan setiap baseline memiliki status `lab-passed`, evidence nonkosong, dan seluruh required checks. Fixture atau build tidak memenuhi login/frame/input nyata.

1. Catat versi OS, arsitektur **Electron dan helper**, compiler, commit aplikasi, hash helper, dan versi server. Host/user/password tidak dimasukkan ke evidence publik.
2. Verifikasi fingerprint server melalui jalur lab tepercaya. Login melalui dialog lokal. Catat kegagalan unknown certificate dan pin mismatch secara terpisah; jangan memakai certificate-ignore.
3. Di tab embedded, buka aplikasi teks kosong untuk uji. Ketik `bridge-proof`, pastikan output terlihat, lalu tutup tanpa menyimpan. Jangan memakai spreadsheet/dokumen operasional sebagai sasaran input.
4. Uji dua sesi dengan akun terpisah (akun yang sama tidak cukup: server menyambungkan koneksi kedua ke sesi yang ada dan memutus yang pertama, teramati dari klien Windows pada 16 Oktober; helper crash, wrong-credentials dan pemutusan TCP keras sudah teramati dari macOS arm64 dan Windows; untuk pemutusan dari Windows dipakai forwarder loopback `work/netcut-20261016/forwarder.mjs`), close/cancel (cancel saat connecting juga dapat dilatih tanpa server: `RDP_LOOPBACK_REPEAT=50 npm run test:native-network`; bukan pengganti uji cancel live), helper crash, salah password, dan interupsi jaringan **pada sesi disposable**. Host operasional tidak boleh dimatikan jaringannya atau dilockout untuk mengejar checklist.
   - **resize** (sudah diimplementasikan lewat display control; teramati live pada macOS arm64 → Windows Server 2019 dan dari klien Windows OPC → Windows Server 2019 pada 16 Oktober, lihat `RDP-SPIKE-STATUS.md`; baseline Windows 11/Intel belum): hubungkan, tunggu desktop tampil, lalu ubah ukuran jendela. Desktop remote harus mengikuti area layar dalam sekitar 1 detik tanpa sesi terputus dan tanpa dialog password. Catat ukuran footer sebelum/sesudah, versi server, dan bila server tidak mengikuti, catat itu sebagai batas server (bukan lulus). Ukuran harus kembali benar setelah jendela dikembalikan. Pra-validasi tanpa server nyata: `npm run test:native-integration` menjalankan helper terhadap server FreeRDP di loopback (bukan Windows RDS); hasilnya tidak mengisi evidence lab.
   - **reconnect** (tombol Hubungkan ulang): putuskan atau hentikan helper pada sesi disposable, tekan Hubungkan ulang; dialog harus menampilkan pengguna@host:port dan meminta password lagi; tab lama harus diganti. Pin tetap diperiksa pada koneksi baru.
   - **paket r5 (teramati live dari OPC pada 16 Oktober; hanya dengan app r5 dan helper r4 yang berpasangan):** minus dan titik dari otomasi (tombol keypad) sampai ke konsol di dalam sesi; F-keys diteruskan (F11 hilang sebelum sesi OPC, jadi tidak dapat diuji lewat otomasi); dua tab ke host yang sama berlabel `host` dan `host (2)`; bila akun yang sama menyambung lagi, tab pertama menampilkan `Sesi ditutup — Sesi diputus dari sisi server (oleh administrator atau pengguna). (kode 0x00000001)` pada Windows Server 2019 (kode 1, bukan 5). Belum diuji live: CapsLock, NumLock, digit keypad, dan alasan lain (idle, batas logon, logoff administrator).
5. **clipboard** (sudah diimplementasikan; dua arah, mati, batas 32 KiB, file dan multibaris teramati live pada macOS arm64 → Windows Server 2019 pada 16 Oktober, dari klien Windows (OPC) teramati teks dua arah, mati, batas 32 KiB kedua arah dan file di clipboard remote lewat konsol; Notepad/editor, 40000/45000, aturan jendela aktif dan baseline lain belum): hanya dengan teks nonsensitif sekali pakai pada sesi disposable. Dasar protokolnya (dua arah, batas 32 KiB, format file tidak diminta, arah yang mati tidak membocorkan teks) sudah dilatih terhadap server FreeRDP di loopback; yang harus dibuktikan di lab adalah perilaku server Windows.
   - Tanpa kotak centang: salin teks di remote dan lokal, pastikan tidak ada yang berpindah dan tidak ada channel clipboard yang diumumkan.
   - Remote → lokal: salin teks di aplikasi teks kosong remote saat tab aktif; clipboard lokal harus berisi teks itu. Dari tab latar tidak boleh menimpa clipboard lokal.
   - Lokal → remote: salin teks lokal, klik canvas sesi (fokus), tempel di remote.
   - Batas: teks di atas 32 KiB harus ditolak utuh (tidak terpotong); salin file di remote/lokal tidak boleh menawarkan file.
   - Di macOS gunakan Ctrl+C/Ctrl+V di dalam sesi remote: Cmd dipetakan ke tombol Windows. Jendela aplikasi harus fokus agar teks remote ditulis ke clipboard lokal.
   - Tempel teks multibaris dari remote ke Notepad klasik dan editor modern, serta sebaliknya; catat apakah baris baru benar (helper selalu mengirim LF ke aplikasi dan CRLF ke remote; kebutuhan CRLF pada clipboard lokal Windows belum diverifikasi).
   Catat hasil per arah dan jangan memakai kredensial, token, atau data operasional sebagai isi clipboard.
6. Simpan laporan teredaksi yang membedakan pass/fail/not-run. Screenshot yang berisi aplikasi operasional tidak boleh dimasukkan. Screenshot build/fixture harus berlabel fixture.

Edit status/checks hanya dari hasil yang diobservasi. Stack decision tetap `pending-live-evidence` sampai semua platform dan semua check lulus. Test gate tidak memverifikasi keaslian evidence; review manusia atas evidence tetap diperlukan.

Kredensial, fingerprint/identitas host privat, raw traces, dan salinan dokumentasi operasional tidak termasuk evidence yang dikomit. Folder `lab/private/` diabaikan Git bila pemilik membutuhkan catatan endpoint lokal.
